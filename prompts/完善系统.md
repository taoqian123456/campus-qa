## 1. ★ 核心：让系统"有头脑"（智能兜底 + 推荐 + 引导）

### 1.1 未命中时的专业回复（必做，用户点名）

现状问题：检索不到内容时，回答"资料库中未找到相关信息"——生硬、显得系统笨。

改造目标（三段式专业回复）：
```
① 诚恳说明（不冷冰冰）："抱歉，在现有知识库中没有检索到与您问题直接相关的内容。"
② 主题引导（体现"知道有哪些知识"）："不过，根据知识库内容，与『转专业』最相关的主题有：
   《学籍管理规定》《转专业管理办法》，您可以从这些方向继续查询。"
③ 换问法建议（教用户提问）："也可以尝试更具体的问法，例如：『转专业需要什么申请材料？』"
```

**提示词（贴给 Roo Code）**：

```
继续我的毕业设计项目（后端 backend/，前端 frontend/index.html）。

请实现"智能兜底回复"：当 RAG 检索不到相关内容（检索结果为空、或相似度分数低于阈值、或回答命中兜底分支）时，
不要只回复"资料库中未找到相关信息"，而是生成三段式专业回复：
1. 诚恳说明：抱歉没检索到直接相关内容（措辞礼貌、专业，参考客服话术）
2. 主题引导：用关键词分类器（jieba 分词 + 预置主题关键词表，如：转专业/选课/奖学金/保研/毕业/学籍/图书馆）判断用户问题属于哪个主题，
   从 documents 表 / 索引元数据中找出该主题下的文档名，列出来作为"可能相关的资料"
3. 问法建议：根据问题类型（条件类/流程类/时间类/材料类），给出 1-2 个更具体的示例问法
实现位置：qa/qa_handler.py 的 answer_question 兜底分支。
另外把主题关键词表放在 config.py（THEME_KEYWORDS 字典），方便论文里写"设计了主题引导机制"。
验收：① 问一个知识库里没有的问题（如"学校有几个食堂"）→ 回复包含说明+相关主题文档+问法建议；② 问"转专业需要什么条件"→ 正常回答不受影响。
```

### 1.2 推荐相关问题（必做）

```
继续。在智能兜底的基础上增加"推荐问题"：
1. 后端新增接口 GET /api/chat/recommend?question=xxx：
   用检索到的 top-3 相关文档块，让 DeepSeek 生成 3 个"用户可能接着问的问题"（要求：必须基于检索到的内容，短句，10字内）
2. 前端在聊天页：当回答走了兜底分支（或回答末尾），显示"你可能还想问："+ 3 个可点击问题，点击后直接发送该问题
3. 接口超时或失败时静默降级（不显示推荐即可，不影响主流程）
验收：问一个模糊问题 → 兜底回复下方出现 3 个推荐问题 → 点击 → 正常提问。
```

### 1.3 相关度分数展示（必做，答辩显专业）

```
继续。让回答显示"相关度"：
1. 后端 answer_question 返回中增加 confidence 字段：
   - 检索最高相似度分数 >= 0.6：confidence = 高分（如"相关度 高"）
   - 0.4-0.6：中
   - < 0.4 或未命中：低（此时走智能兜底）
   - 阈值做成 config.py 配置（CONFIDENCE_HIGH=0.6, CONFIDENCE_LOW=0.4），实验后可以调
2. 前端：AI 回答气泡下方显示"相关度：高/中/低"（高=绿色、中=橙色、低=灰色），旁边显示来源文档名
验收：问知识库内问题显示"相关度：高"；问模糊问题显示"中/低"并走兜底。
```

### 1.4 多轮对话上下文（强烈推荐，P4 预留的 history 参数用起来）

```
继续。启用多轮对话上下文：
1. qa_handler.answer_question 的 history 参数：把当前会话最近 3 轮对话（用户问题+AI回答，截断各100字）拼进 System Prompt，
   让 AI 能理解"它"这类指代（如用户接着问"那需要什么材料？"）
2. 前端发送时带上当前会话的消息历史（前端已有消息列表，取最近3轮即可）
3. 注意：历史只用于理解指代，检索仍只基于最新问题（保持 RAG 纯净）
验收：先问"转专业需要什么条件？"，再问"那流程是什么？"→ 第二次回答能理解"那"指转专业，不重复解释条件。
```
